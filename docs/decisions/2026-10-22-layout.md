# 2026-10-22 · Repository layout and C03 scope

상태: 사용자 승인 후 C03 경로 구현.

데이터 사실은 datasets, 업무 정의·참조 SQL은 benchmarks, 실행은 src/driftlens_benchmark로 나눈다. agent와 benchmark는 JSONL로 연결하고 탐지와 채점을 분리한다.

이 분리는 [SWE-bench](https://github.com/SWE-bench/SWE-bench)의 실행/평가 경계, [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)의 선언형 task, [Spider2](https://github.com/xlang-ai/Spider2)의 데이터/정답/제출 분리를 참고했다. 원래 조사 revision과 더 넓은 목표는 [설계 기록](../proposals/2026-10-repository-redesign/research-and-migration.md)에 남긴다.

현재 C03과 3컬럼 DB부터 완주했다. 6개 테이블을 미리 빈 구현으로 만들지 않았다. 미지원 후보는 catalog에만 둔다. public 레코드는 private truth에서 추출하고, 실행 실패와 의미 변경 라벨을 구분한다.

구현 선택:
- Python src package와 설치된 JSON Schema 리소스.
- YAML declarative assets, JSONL 관측과 예측.
- SQLGlot AST의 보수적인 부분집합 인식. 미지원은 유보.
- 한 요청/한 프로세스, 매주 as-of snapshot, fake-provider 오프라인 E2E.
- 전체/부분/실패 실행 상태와 명시적 채점 분모.
- UTC 월요일 변경일을 선택한 development smoke.
- 기존 agent 프로토콜은 유지하고 records/v2만 확장.

후속 범위: 6테이블 dataset, 추가 케이스, 파일 제출/HTTP adapter, L0–L2, container 격리, temporal score. 현재 unisolated 결과를 공식 held-out 성능으로 표시하지 않는다.
