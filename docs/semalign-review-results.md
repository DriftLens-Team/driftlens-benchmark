# SemAlign 설계 검토·개선 및 검증 보고서

검증일: 2026-10-28

## 1. 결론

driftlens-data → driftlens-sql-agent → driftlens-benchmark의 데이터 준비, SQL·답변 생성, 생성 검수, 의미 변화 탐지, 채점을 연결하고 전체 기간을 실행했다. 수정 데이터와 모의 에이전트는 각각 364건 모두 검수를 통과했다. 실제 모델은 364건 중 270건(74.2%)이 통과했고, 93건은 정의 조건 불충족으로 탈락했으며 1건은 SQL 실행에 실패했다.

평가 체계는 생성 오류와 의미 변화를 구분해 기록한다. 실제 모델의 모든 출력을 신뢰할 수 있는 상태는 아니며, SQL 탐지기의 지원 범위와 독립 평가 데이터도 추가 확장이 필요하다.

## 2. 데이터 구성과 난이도

| 항목 | 확인 결과 |
|---|---|
| 형식 | UTF-8 JSONL, 관측 한 건당 한 줄·최상위 10필드 |
| 규모 | 7개 지표 × 52주 = 364건 |
| 기간 | 2024-09-02 시작 주부터 2025-08-25 시작 주까지 |
| 원본 보고값 | 정수 260건, 소수 103건, null 1건 |
| 단위 | count: 건수·고객 수, cents: 정수 센트, ratio: 소수 비율 |
| 원본 정답 | 정의 변경 94건, 정상 270건 |
| 비교 쌍 | 112쌍: 변경 24쌍, 미변경 88쌍; 어려운 음성 44쌍 |
| 원천 DB | 주문 61,948건, 주문 품목 90,900건, 상품 10개, 매장 6개 |

원본 로그는 SQL 실행값과 문장 템플릿으로 생성한 합성 데이터다. 실제 모델 생성 데이터는 별도 실행으로 관리한다. 주간 범위는 시작 포함·끝 제외이며, 실제 값 0, 계산 불가 null, 실행 실패를 구분한다.

| 관측 수준 | 질문·답변·수치 | SQL | 정의 설명 |
|---|---|---|---|
| L0 | 제공 | 없음 | 없음 |
| L1 | 제공 | 제공 | 없음 |
| L2 | 제공 | 없음 | 제공 |
| L3 | 제공 | 제공 | 제공 |

L0~L3는 같은 표본의 공개 필드를 달리한 자료다. 독립 표본 1,456건으로 합산하지 않는다.

보고값 기준 정의 간 상대 차이의 52주 중앙값은 음식 주문 −92.5%, 활성 고객 −20.3%, 평균 주문액 +5.9%다. 각각 easy·medium·hard 표기와 대응하지만, 이는 현재 데이터의 수치 효과이며 모델 정확도나 모든 관측 수준의 난이도를 뜻하지 않는다. 주간 값 변화가 있어도 정의가 같은 대조군을 함께 평가해야 한다.

## 3. 설계와 개선 사항

| 구성 | 책임과 정보 범위 |
|---|---|
| driftlens-data | 원천 DB, 기준·변경 정의, 시나리오, 독립 참조 계산 |
| driftlens-sql-agent | 현재 정의 하나와 해당 시점까지의 DB로 SQL·답변 생성 |
| benchmark 생성 검수 | 실제 SQL, 참조값, 보고값·답변, 반례 실행을 비공개로 검사 |
| benchmark 탐지·채점 | 공개 로그와 기준 정의로 탐지하고 비공개 정답으로 채점 |

에이전트에는 미래 정의·정답·원본 정답 SQL을 전달하지 않는다. 주 탐지기는 DB를 사용하지 않는다. DB 수치 비교는 별도 진단이다. 생성 통과 관측만 공개하며 탈락·미검증·실행 실패는 원인과 함께 별도 보존한다.

benchmark의 구현은 `datasets`(입력·정의), `adapters`(외부 에이전트), `validation`(생성 검수), `semantics`·`detectors`(의미 추출·탐지), `evaluation`(채점), `contracts`(입출력 형식)로 나눴다. 실행 결과의 `private`에는 검수 자료, `public/L0~L3`에는 탐지기에 제공할 자료를 저장한다.

| 발견한 문제 | 적용한 개선 | 확인 결과 |
|---|---|---|
| 빈 주에서 고객 수가 null, 성장률이 0으로 계산됨 | COUNT와 SUM의 빈 집합 처리 수정 | 독립 반례에서 기대값과 일치 |
| 전주 시작 정각을 불완전한 자료로 오인 | 날짜·timestamp 경계를 맞춰 비교 | 정각 및 ±1초 경계 검증 |
| 독립 참조 검사에서 주차·0/null·세율 누락 | 원천 CSV로 7개 지표·2개 정의·52주 독립 계산 | 728개 값 불일치 0 |
| 날짜 접미사와 이중 반올림이 답변을 왜곡 | 날짜 매개변수 바인딩, 잘못된 timestamp·SQL ROUND 거절 및 수정 피드백 | 에이전트 회귀 테스트 통과 |
| 정수 나눗셈·잘못된 최초 주문·미해석 SQL 절의 오인 | SQL 전체 구조·집계·기간·null 규칙 검사 강화 | 지원 밖 형태는 기권 |
| 검수기와 탐지기의 추출기 공유 | 별도 behavioral 검수 정책 추가 | 탐지 성공 여부로 표본을 선별하지 않음 |
| 반례의 실행 오류가 원본 DB 불일치로 표시됨 | DB·반례·참조·SQL 단계별 오류 분리 | 저장 응답 363건 재검수, 진단 8건 정정·판정 변경 0 |
| 테스트 결과와 생성 데이터 확인이 어려움 | 전체 실행 스크립트와 HTML·CSV·JSONL 증적 생성기 추가 | 명령·시각·종료 코드·원본 해시 기록 |

동일한 10종 반례의 560개 SQL 비교에서 불일치는 수정 전 14개에서 수정 후 0개로 줄었다. 원본 DB의 728개 oracle 보고값은 바뀌지 않았다. 새 로그에서는 SQL 69행만 변경됐고 다른 관측 필드와 정답은 동일하다. 기존 데이터 파일 9개의 해시도 유지됐다.

생성 검수에는 두 정책이 있다. structural은 SQL 의미 추출기를 탐지기와 공유하는 개발 일관성 검사다. behavioral은 실제 DB와 9종 반례에서 SQL·oracle·독립 Python 계산의 결과를 비교한다. behavioral의 통과는 유한 사례에서의 일치이며 모든 SQL의 의미 동치를 증명하지 않는다.

탐지는 SQL·설명에서 집계 대상, 집계 방법, 모집단, 금액 기준, 조건, 기간, null 처리, 단위를 비교한다. LOG는 관측과 기준 정의, T1은 두 관측의 의미, T2는 주별 시계열을 평가한다. T2는 현재까지의 관측만 사용하며 같은 변화가 연속 2주 확인되면 최초 경보를 고정한다. 해석할 수 없는 입력은 기권하고 판정률을 함께 보고한다.

## 4. 전체 실행 결과

Windows에서 data는 Python 3.12.14, agent와 benchmark는 Python 3.11.9로 실행했다. 전체 절차는 23:15~23:39 KST에 수행됐다. 실제 모델은 Upstage solar-pro4-260806이며, 364개 요청의 생성·검수에 약 17분 20초가 걸렸다.

| 자동 검증 | 최종 결과 |
|---|---|
| benchmark | 181개 통과, Windows symlink 권한 조건 1개 제외 |
| SQL agent | 59개 통과 |
| data | 10개 통과 |
| 코드 검사·패키지 빌드 | Ruff, benchmark·agent wheel 성공 |
| 독립 데이터 검사 | 560개 반례 비교·728개 원천 참조값 불일치 0 |

benchmark의 최종 181개 결과는 진단 표시 오류 수정 후 전체 테스트를 다시 실행한 기록이다. 기본 자동 테스트는 실제 모델을 호출하지 않는다.

| 실행 | 시도 | 통과 | 탈락 | 미검증 | 실패 |
|---|---:|---:|---:|---:|---:|
| 기존 합성 SQL 재검수 | 364 | 295 | 69 | 0 | 0 |
| 수정 데이터 재생성·검수 | 364 | 364 | 0 | 0 | 0 |
| 모의 에이전트 통신·계산 검증 | 364 | 364 | 0 | 0 | 0 |
| 실제 모델 생성·검수 | 364 | 270 | 93 | 0 | 1 |

모의 에이전트는 정해진 의미로 SQL을 생성하는 연결 검사다. 실제 모델의 언어 이해 성능으로 해석하지 않는다. 실제 모델의 탈락 결과를 재호출해 교체하지 않았다. 실행 완료와 전체 생성물의 검수 통과는 서로 다르다.

| 실제 모델 지표 | 통과 / 시도 | 탈락 | 실패 |
|---|---:|---:|---:|
| 음식 주문 | 11 / 52 | 41 | 0 |
| 음료 주문 | 52 / 52 | 0 | 0 |
| 활성 고객 | 52 / 52 | 0 | 0 |
| 신규 고객 | 51 / 52 | 1 | 0 |
| 평균 주문액 | 52 / 52 | 0 | 0 |
| 매출 성장률 | 0 / 52 | 51 | 1 |
| 평균 세율 | 52 / 52 | 0 | 0 |

대표 오류는 독립 DB 실행으로 재확인했다. 음식 주문은 beverage만 제외해 다른 품목이 섞인 주문을 포함했다(반례: 3건, 기대 2건). 신규 고객은 고객 대신 주문 행을 세었다(실제 DB: 16명, 기대 10명). 성장률은 불완전한 전주에서 null 대신 숫자를 반환하거나, 조건을 WHERE에 넣어 단일 null 대신 0행을 반환했다. 답변 숫자가 SQL 결과와 같아도 업무 정의가 올바르다는 뜻은 아니다.

## 5. 탐지 결과와 해석

실제 모델의 평가 대상은 검수 통과 관측 270건, 적격 비교 쌍 81개, 전체 주가 적격인 시계열 4개다. 계획 대비 관측 94건·쌍 31개·시계열 3개가 제외됐다.

실행 후 발견한 진단 표시 오류는 수정하고 저장된 응답 363건을 재검수했다. 반례에서 0행을 반환한 8건의 실제 DB 검사 표시가 정정됐으며 통과·탈락 판정과 평가 분모는 바뀌지 않았다. 모델 재호출은 없었고 원본 실행 파일의 해시도 유지됐다.

| 수준 | LOG F1 | LOG 판정률 | T1 F1 / 판정률 | T2 F1 / 판정률 |
|---|---:|---:|---:|---:|
| L0 | 0.000 | 0.0% | 0.000 / 0.0% | 0.000 / 0.0% |
| L1 | 0.981 | 61.9% | 1.000 / 60.5% | 1.000 / 75.0% |
| L2 | 1.000 | 100.0% | 1.000 / 100.0% | 1.000 / 100.0% |
| L3 | 1.000 | 100.0% | 1.000 / 100.0% | 1.000 / 100.0% |

L0는 숫자만으로 정의 변경을 확정하지 않아 모두 기권했다. L1은 SQL 103건을 해석하지 못했고 양성 2건을 놓쳤다. 높은 F1과 제한된 판정률을 함께 봐야 한다.

L2·L3의 정의 설명은 호스트가 현재 profile에서 기록한 정본 문장이다. 이 조건의 만점은 자유로운 자연어 설명 이해나 미지 SQL 일반화를 입증하지 않는다. 수정 합성·모의 실행의 전체 7개 시계열 결과와 실제 모델의 적격 4개 시계열 결과를 합산하지 않는다.

## 6. 재현 방법과 산출물

세 저장소를 같은 상위 폴더에 두고 각 README에 따라 가상환경을 준비한다. data는 `uv sync`, benchmark는 개발 의존성까지 설치한다. 다음 명령은 benchmark 폴더에서 실행한다. 출력 경로는 새 폴더를 지정한다.

```powershell
.venv/Scripts/python.exe scripts/run_semalign_acceptance.py --data-root ../driftlens-data --data-python ../driftlens-data/.venv/Scripts/python.exe --agent-python ../driftlens-sql-agent/.venv/Scripts/python.exe --out runs/semalign-reproduction --live --env-file ../driftlens-sql-agent/.env
```

명시한 환경 파일에는 UPSTAGE_MODEL과 UPSTAGE_API_KEY를 설정한다. 실제 모델 없이 재현하려면 `--live`와 `--env-file`을 제외한다. 같은 모델이어도 응답과 수치는 달라질 수 있다.

```powershell
.venv/Scripts/python.exe scripts/semalign_evidence.py --run runs/semalign-reproduction/live --out runs/semalign-evidence --report runs/semalign-reproduction/live-report-L1.json --report runs/semalign-reproduction/live-report-L3.json --test-log runs/semalign-reproduction/logs/benchmark-tests.stdout.txt
```

| 파일 | 용도 |
|---|---|
| index.html | 실행별 결과 화면 안내 |
| live/index.html | 실제 모델의 요약·생성 SQL/답변·실행 기록 |
| live/generated.csv | 실패를 포함한 전체 364개 시도 |
| live/observations.jsonl | 검수 통과 270개 공개 관측 |
| live/result.json, execution.txt | 집계·해시·재현 명령·테스트 로그 |
| original, regenerated, fake 폴더 | 동일 형식의 비교 실행 증적 |
| screenshots 폴더 | 실행 중·완료·생성 SQL·테스트 화면 원본 |
| diagnostics-audit.json, verification 폴더 | 저장 응답 재검수 집계와 최종 자동 테스트 로그 |

공유 증적에는 공개 자료와 집계만 담는다. API 키·비공개 정답·DB snapshot은 포함하지 않는다. 원본 실행은 로컬 acceptance 폴더에 보존한다.

## 7. 적용 범위

현재 지원하는 7개 지표의 개발·회귀 검증에 사용할 수 있다. 실제 모델의 음식 주문·성장률 생성 품질과 SQL 탐지기의 판정률은 추가 개선 대상이다. 개발에 사용하지 않은 SQL·설명·시나리오와 독립 검수자를 확보하기 전에는 범용 정확도를 주장하지 않는다. 외부 제출을 평가할 때 필요한 OS 수준의 격리는 이번 범위에 포함하지 않았다.
